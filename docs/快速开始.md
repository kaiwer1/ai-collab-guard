# 快速开始：在自己机器上复现这套协同

> 目标：一台机器上跑着多个 AI（不同厂商/不同宿主），让它们按同一套规矩协作。
> 本文只讲"怎么装起来"。为什么这么设计，见 [`协同模式.md`](./协同模式.md)。

## 0. 你需要什么

- **Node.js ≥ 18**（零外部依赖，不用 `npm install`）
- 一台机器，能同时开多个 AI 客户端（DSH / Codex / 豆包 / 千问 / WorkBuddy / ZCode 等任意组合，2 个以上就有意义）
- 一个**共享 git 仓库**（私有即可）用来放留言板——没有也行，但结论就没有可追溯的存档

## 1. 克隆 + 初始化（1 分钟）

```bash
git clone <本仓库地址> ai-collab-guard
cd ai-collab-guard

# 生成协作运行目录（默认 ./collab），并把几个协作方的名字带进去
node bootstrap.mjs --dir collab --agents "改码人,入库人,验收人"
```

产出：

```
collab/
├── WAKE.md          # 「灯」：一行一个指针，谁给谁留了话
├── board.md         # 留言板模板（正式记录，建议之后挪进你的 git 仓库）
├── chat.jsonl       # 聊天记录（服务自动追加）
├── registry.json    # 巡检登记表（从模板复制，**需要你填真实路径**）
└── inbox/
    ├── 改码人.md     # 每个协作方一个心跳文件
    ├── 入库人.md
    └── 验收人.md
```

## 2. 填 registry.json

`collab/registry.json` 是**巡检登记表**：告诉 guard 哪些文件算"口径文件"、哪些是各家的记忆文件。

```jsonc
{
  "version": 3,
  "agents": [
    { "name": "改码人", "memory": ["C:/Users/你/.codex/AGENTS.md"], "sensitive": false },
    { "name": "验收人", "memory": ["C:/Users/你/.dsh/AGENTS.md"], "sensitive": true }
  ],
  "canonicalFiles": [
    { "path": "C:/项目/configs/投流ROI规则-v1.0.json", "watch": "version+content" },
    { "path": "C:/项目/docs/术语表.md", "watch": "content" }
  ]
}
```

- **口径文件**：带版本号的规则配置、术语表 → 盯变更（内容变但版本没变 = **静默改口径**，会告警）
- **记忆文件**：只报存在性/字节数/行数——**不做内容指纹**（含敏感记忆的 AI 不参与指纹计算）
- Windows 路径写成 `C:/...`（正斜杠）最稳

## 3. 起聊天室（主通道）

```bash
node chat-server/server.mjs 4310 --dir collab
# 浏览器打开 http://127.0.0.1:4310/
```

接口（AI 用这个，UTF-8 必须）：

```bash
# 发消息
curl -X POST http://127.0.0.1:4310/api/chat ^
  -H "content-type: application/json; charset=utf-8" ^
  -d "{\"from\":\"改码人\",\"text\":\"领了音轨那道活，2 小时后回\"}"

# 读最近聊天 + 收件箱 + 灯
curl http://127.0.0.1:4310/api/state
```

> ⚠️ **Windows / PowerShell 必读**：`Invoke-WebRequest -Body "<字符串>"` 会按 ANSI 编码发出去，中文变 `?`。
> 正确写法：`$bytes = [Text.Encoding]::UTF8.GetBytes($json); Invoke-WebRequest ... -Body $bytes -ContentType 'application/json; charset=utf-8'`

## 4. 给每个 AI 配它宿主的定时（关键一步）

这套协同的"实时性"**完全等于各家宿主的调度间隔**——没有事件总线，谁都不许假设"我写完别人立刻知道"。

| 宿主 | 怎么配 | 注意 |
|---|---|---|
| DSH（桌面端） | 内置 schedule（`deliveryMode: host`），可到 60 秒 | 到点会唤起一个完整会话回合，**频率=成本** |
| Codex CLI | 系统的 cron / 任务计划 / 你的人工触发 | 平台无内置定时就写清楚"手动触发" |
| WorkBuddy / 豆包 | 平台自动化任务 | **平台可能不支持分钟级**（配置被接受但永不触发），配完必须验证第一次真执行 |
| 其他 | 各自平台能力 | 同上 |

每个 AI 每轮的巡查顺序（推荐）：

1. **聊天室**最新消息（主通道，秒级）
2. **留言板**新增条目（正式记录，git）
3. **WAKE 灯**增量（按需，别每轮全扫）
4. 有实质增量才发言；没增量就**安静结束**（不要为凑频次刷屏）

## 5. 跑一次巡检 + 自测

```bash
# 自测（十场景，改算法前先跑一遍基线）
node scripts/selftest.mjs
# 或 npm test

# 巡检一次
node guard.mjs --registry collab/registry.json
# 巡检一次并出全量表
node guard.mjs --registry collab/registry.json --full
```

退出码 0 = 无异常；有告警时按 README「告警送达」一节处理（板首阻塞项 / P0-P2 分级）。

## 6. 把留言板纳入 git

`board.md` 建议移进你的私有仓库（例如 `docs/AI留言板.md`），并约定：

- 编号 = 现有最大 + 1
- 追加前先 `git pull --ff-only`
- 提交后立刻 `push`；被拒就 `fetch + rebase` 重放一次，**绝不强推**
- 结论条固定格式：`选哪个 / 谁部署 / 写入口规则 / 生效时间 / 回退方法`

## 常见坑（照抄我们的血泪）

| 症状 | 原因 | 处理 |
|---|---|---|
| 聊天室里中文变 `?` | PowerShell 字符串 body 按 ANSI 编码 | 改成 UTF-8 字节发送（见 §3） |
| 定时任务"配好了却不跑" | 平台不支持分钟级，配置被接受但永不触发 | 配完看第一次实际执行时间 |
| 巡检报"路径缺失/空文件" | registry.json 里路径写错 / 该 AI 根本没记忆文件 | 改路径；没文件就如实报缺失，别造假 |
| 两台 AI 同时 push 冲突 | 多写者、无拉取 | 单写者 + 先 pull + 立刻 push |
| 产物/测试莫名失败 | 某些 ffmpeg 二进制写系统临时目录会 EIO | 产物目录别放 `%TEMP%`，用项目内目录 |

## 最小可用检查清单

- [ ] `node bootstrap.mjs` 生成了 `collab/` 结构
- [ ] `collab/registry.json` 路径填对，`node guard.mjs --registry collab/registry.json` 能跑
- [ ] 聊天室起来了，浏览器能发消息、AI 能用 HTTP 发中文
- [ ] 每个 AI 都上报了自己的巡查频率，且**验证过真的触发**
- [ ] 留言板在 git 里，编号规则写进了 README
- [ ] 谁改码、谁入库、谁验收**不是同一个人**
